# MS3DH TRIPE — مشروع الموقع

## النشر على Netlify
1. فك ضغط المشروع، ثم ارفع **كل محتويات المجلد** إلى مستودع Git متصل بـ Netlify أو انشر المجلد مع الحفاظ على بنية الملفات.
2. تأكد من وجود `index.html` و`netlify.toml` ومجلد `netlify/functions/discord.mjs`.
3. من Netlify → Site configuration → Environment variables أضف: `DISCORD_BOT_TOKEN` و`DISCORD_GUILD_ID`.
4. من Discord Developer Portal فعّل **Server Members Intent** لجلب الأعضاء، وأضف البوت إلى السيرفر بصلاحيات القراءة المناسبة. ثم أعد النشر.
5. افتح «إدارة الموقع» ثم «مزامنة Discord». ستظهر معلومات السيرفر والرتب والأعضاء المسترجعين.

## ما تم تضمينه
- واجهة عربية RTL ومتجاوبة مع حركات انتقال وتأثيرات سينمائية.
- أقسام الإدارة العليا، الفرق، الأخبار، القوانين والإجراءات، سجل الأعضاء، البثوث، التقديم والدعم.
- لوحة إدارة بنفس طابع التصميم، مع إضافة وتعديل وحذف للأعضاء والأخبار والبثوث والقوانين والفرق.
- Netlify Function لجلب بيانات السيرفر والرتب والأعضاء من Discord دون كشف توكن البوت في المتصفح.

## ملاحظات مهمة
- بيانات لوحة الإدارة تحفظ في `localStorage` على الجهاز/المتصفح نفسه فقط؛ لا تُعدّ نظام صلاحيات آمنًا ولا تتزامن بين الأجهزة. للحماية الفعلية وحفظ مركزي، يلزم نظام مصادقة وقاعدة بيانات.
- لا تضع توكن البوت داخل `index.html` أو أي ملف عام.
- جلب الأعضاء يتطلب تفعيل Server Members Intent.
- حالة البث اليدوية لا تصبح تلقائية إلا بعد ربط API رسمي للمنصة المطلوبة.
- راجع القوانين الافتراضية واجعلها مطابقة لقواعد مجتمعك.

## ملفات الأعضاء والترقيات
- من إدارة الموقع → الأعضاء والإدارة، يمكنك إضافة رابط صورة العضو، وDiscord User ID، والرتبة القادمة، وتاريخ ووقت الترقية، ونسبة التقدم.
- اضغط على بطاقة عضو الإدارة أو صف العضو في سجل الأعضاء لفتح ملفه التعريفي.
- إذا تمت مزامنة العضو من Discord، تُستخدم صورة Discord واسم الحساب المتاح. لربط عضو الإدارة يدويًا بحسابه، أدخل Discord User ID الصحيح.
- عدّاد الترقية يحسب الوقت المتبقي من التاريخ الذي تحدده. إذا لم تحدد موعدًا، سيعرض الموقع أن الموعد غير محدد.

## نظام التقديم الداخلي مع Discord
النظام الجديد يقدّم نموذجًا داخل الموقع نفسه، ويحفظ الطلبات في Supabase، ويتيح مراجعتها من لوحة إدارة الموقع وقبولها أو رفضها. لا يحتاج المتقدم إلى رابط خارجي.

### إعداد قاعدة بيانات الطلبات (مرة واحدة)
1. افتح Supabase SQL Editor وشغّل الملف `supabase-applications.sql` الموجود في المشروع.
2. في إعدادات Netlify أضف متغيرات البيئة التالية:
   - `SUPABASE_URL` — رابط مشروع Supabase.
   - `SUPABASE_SERVICE_ROLE_KEY` — مفتاح الخدمة السرّي (لا تضعه في `index.html`).
   - `APPLICATIONS_ADMIN_KEY` — مفتاح إداري قوي لإدارة التقديم (يمكن استخدامه للدعم أيضًا).
   - `SUPPORT_ADMIN_KEY` — اختياري؛ مفتاح منفصل لإدارة طلبات الدعم، إن لم تضعه يمكن استخدام `APPLICATIONS_ADMIN_KEY`.
   - `DISCORD_BOT_TOKEN` و`DISCORD_GUILD_ID` — توكن البوت ومعرّف السيرفر.
   - `DISCORD_APPLICATIONS_WEBHOOK_URL` — رابط Webhook لقناة الإدارة الخاصة باستقبال طلبات التقديم؛ أنشئه من إعدادات القناة في Discord ثم ضعه هنا فقط، ولا تضعه في HTML أو GitHub.
   - يمكن تعيين `DISCORD_ACCEPTED_ROLE_ID` كرتبة افتراضية، أو تحديد رتبة مختلفة من لوحة طلبات التقديم.
3. امنح البوت صلاحية **Manage Roles**، واجعل أعلى رتبة للبوت أعلى من الرتبة التي سيمنحها. يجب أن يسمح إعدادات الخصوصية لدى العضو باستقبال رسائل مباشرة من البوت كي تصله رسالة القبول/الرفض.
4. في Supabase SQL Editor شغّل ملف `supabase-applications.sql`، بما في ذلك أمر `ALTER TABLE` لإضافة نوع التقديم للمشاريع الموجودة.
5. أنشئ Webhook في قناة Discord الخاصة بالإدارة وانسخ رابطه إلى `DISCORD_APPLICATIONS_WEBHOOK_URL` في Netlify Environment variables.
6. أعد نشر الموقع. افتح إدارة الموقع ← طلبات التقديم، وأدخل `APPLICATIONS_ADMIN_KEY` عند طلبه. من هناك افتح/أغلق التقديم وحدد رتبة القبول وراجع الطلبات حسب نوعها.
7. لبوابة الدعم: شغّل SQL المحدث في `supabase-applications.sql` لإنشاء جدول `ms3dh_support_tickets`. افتح إدارة الموقع ← طلبات الدعم، وأدخل `SUPPORT_ADMIN_KEY` أو `APPLICATIONS_ADMIN_KEY`. الردود تُحفظ في قاعدة البيانات وتُرسل برسالة خاصة عبر Discord إذا كان البوت يستطيع مراسلة العضو.

### سير العمل
- عند فتح التقديم يظهر النموذج داخل صفحة الموقع، وعند إغلاقه لا يظهر النموذج.
- الطلبات تحفظ في قاعدة البيانات وتظهر في قائمة الإدارة، وليس في قائمة عامة للزوار.
- القبول يضيف رتبة Discord المحددة ثم يحاول إرسال رسالة خاصة للمتقدم. الرفض يحاول إرسال رسالة رفض.
- إذا منع العضو الرسائل الخاصة، قد يفشل الإشعار؛ تظهر حالة الإرسال في استجابة الخدمة ولا يمكن ضمان وصول رسالة خاصة في هذه الحالة.
- إعدادات فتح/إغلاق التقديم والطلبات مشتركة بين الزوار والأجهزة لأنها تحفظ في قاعدة البيانات، بخلاف بقية محتوى الموقع القديم الذي ما زال يستخدم التخزين المحلي.
- لا تضع `SUPABASE_SERVICE_ROLE_KEY` أو `DISCORD_BOT_TOKEN` داخل HTML أو مستودع عام. صلاحية إدارة التقديم والدعم محمية بمفتاح الخادم `APPLICATIONS_ADMIN_KEY` أو `SUPPORT_ADMIN_KEY`.

## حالة البث التلقائية
- تمت إضافة `netlify/functions/streams.mjs` لفحص حالة قنوات Kick كل 60 ثانية.
- أدخل اسم القناة في حقل اسم القناة أو ضع رابط Kick صحيحًا في إدارة الموقع.
- قنوات Kick المباشرة تظهر ببطاقة خضراء وعبارة «مباشر الآن»، وغير المباشرة تظهر أسماؤها فقط في قائمة عمودية.
- يتطلب ذلك نشر مجلد المشروع كاملًا على Netlify. إذا تعذر التحقق من حالة القناة فلا يتم عرضها على أنها مباشرة.
- الفحص التلقائي مخصص لـ Kick؛ المنصات الأخرى تحتاج تكاملًا خاصًا بها.
